# Outlet order: web app, plugin, SaaS, extension, mobile-last

Nontechnical users are reached in outlet order: responsive web app (onboarding, connects, and settings in v1), assistant plugin (MCP-first across the MCP camp, ChatGPT on its own path second), multi-user SaaS, browser extension (digest surface plus visited-page capture with its own ingestion rules), and finally a mobile app (Android first via the store-wrapped web app). Web-first because it grows the shipped FastAPI surface with no store review and later becomes the SaaS frontend; plugin-second because every plugin needs the web build's HTTP API and per-user auth anyway; SaaS third because it overturns the exactly-one-user spec assumption only once real users exist; extension fourth because the habit fits it but capture is a new source tier in disguise; mobile last because the web app already runs everywhere and only store-only features justify native cost. Reordering later is cheap except for SaaS position: moving multi-user earlier reopens the tenancy decision, so that move requires revisiting ADR-0005.
